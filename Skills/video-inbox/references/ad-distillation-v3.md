# 广告蒸馏 v3：逐帧证据与独立复核

用户要求「v3」「100帧分析」「广告蒸馏」或批量 AI 产品广告时读取本参考。该分支替代通用少量抽帧流程；质量优先，候选数量与通过数量分开。

## 1. 先确认资料和范围

- 检查实际媒体、帧目录、时长与已有笔记；不把上次会话摘要、任务完成通知或文件名当成现存证据。
- 每个视频按平台 canonical ID 去重。修订旧稿时先读旧稿，优先新增 v3 版并写 `supersedes`；不删除、不默默覆盖旧稿。
- AI 来源分三档：`creator_claim`（标题/简介自称）、`workflow_visible`（录屏实际呈现工具）、`unknown`。画面有 CG 感不能证明 AI 制作，标题含 AI 也不能证明全流程工具。
- 先判片型：`product_ad` / `mixed_ad` / `tutorial` / `static_design` / `non_product`。宣传片、交通安全、恶搞食品和商品海报教程不可用来凑「优秀纯商品成片」。保留分析价值时列到参考区。
- 已授权批量工作不重复询问数量或模型；按资源安排并发，每片只允许一个写者。`freebuff` 若无图像能力只做元数据和机械校验，不许用像素统计代替视觉语义。

## 2. 采样与证据保存

- 用 ffprobe 验证 duration、width/height、视频流和音频流；网络标题时长与本地媒体时长分别记录。多P总时长不得当成单P缺失。
- 对完整媒体全时域均匀抽100帧，使用真实帧索引/PTS，保留最后可解码帧。短片不足100个独立帧时使用全部独立帧并报告分母，不复制帧凑数。
- 精确100帧任务没有「最短0.5秒」限制。长教程的100帧可以跨全片稀疏分布，不能说只覆盖前一分钟；跨时域不等于连续覆盖全部细节。
- `frame_index.json` 保存 video_id、媒体SHA256、duration、每个 frame_id、源文件、source_frame_index、timestamp_s、SHA256。切点仅作导航，不代表镜头语义或事实。
- 逐帧读图可使用带 frame_id 和真实时码的联系表，每张最多6格（建议2×2、每格宽≥480px）；每批最多6个原始帧。细字、镜头边界、物体身份存疑时放大原图。机械生成拼板不等于已经读过。
- 逐批保存 `frames.jsonl`，每帧独立一行，不用帧区间代替。字段：

```json
{"frame_id":"u001","timestamp_s":0.0,"read_method":"contact_sheet","read_asset":"boards/001.jpg","observation":"瓶体居中，左侧冰块；下缘可见标题字","category":"product","close_up":true,"visible_text":"可读文字；模糊处明确写不可辨","uncertainty":""}
```

- `category` 取 product / ingredient / use_detail / environment / person / ui / text / black / uncertain。`observation` 只写该帧实际可见内容。后续帧仍需实际读，不用「同上」「延续」「据范式」补行。
- `read_method` 是可追溯声明而非防伪凭证。完整100行和图片hash只能证明可核对结构；仍需独立视觉复核，不能靠脚本自证真读。
- 证据存WSL长期目录，不依赖 `/tmp`。含原始媒体/帧表的蒸馏证据在复核完成前不清理；笔记链接至稳定证据目录。普通临时获取链仍按原保留策略。

## 3. 占比只有一套基准

- 基准特写：可辨商品本体、食材质感微距，或商品主导的局部使用动作；人物/环境占主导、工具界面、纯文字、黑场不计。
- 带字幕的商品镜头正常判定；字幕不自动减半。手持商品看主体，不因有手自动排除。定版若商品主导可计；logo纯字卡不计。器具只有在售商品就是该器具，或商品本体可见且为局部操作焦点时计。
- UI中的小预览不是成片特写；黄绿液体不是肤色证据。`ui`、`environment`、`person`、`text`、`black` 的基准 `close_up` 必须为 false。
- `close_up_ratio = true行数 / 实际有效采样数 × 100`，保留原始计数及一位小数。不允许「约28帧→保守22%」、折半帧、剔掉不利样本改分母。未采尾秒不凭空换算成若干帧。
- 有 `uncertain` 时不能报精确占比或通过结论：报告已确认下界、可能上界与待补证帧。欲提供从宽口径，另列明确新增帧ID并从同一帧表重算，不拍脑袋给百分比。
- ≥70% 只是商品特写专场的镜头资格，不能代替制作质量、AI来源、商业适用性和蒸馏质量验收。使用 `selection_status` 分开记录入选/参考/排除及理由。

## 4. v3 笔记内容

保留 source_url、video_id、采样范围、采样密度、获取来源、AI来源证据、证据路径。状态使用独立字段：

```yaml
analysis_version: v3
analysis_status: partial
visual_status: complete
audio_status: unavailable
review_status: pending
content_type: product_ad
selection_status: reference
frame_count: 100
reviewed_frame_count: 100
close_up_count: 79
close_up_ratio: 79.0
```

`analysis_status: complete` 仅在主要论点所需的视觉、声音/文字证据已取得且独立复核通过时使用。视觉100帧完成但未听音，可 `visual_status: complete`、总体 `partial`；不为状态好看补造声音。

正文需有下列信息，避免模板空话：

1. **一句话结论与入选理由**：商品是什么、成片/教程、最值得学什么、有何局限。
2. **可核实内容**：按实际时间段讲清开场、卖点证明、转折、品牌收束；关键语句链接帧ID。录屏中的模型名/参数标明可见来源，读不清即未知。
3. **镜头拆解**：景别、构图、主体/背景、光线/材质、色彩、动作/运镜、剪辑/转场、节奏作用。单帧只能说明状态；动作至少两个时点支持，复杂运动/转场需要视频片段验证。`scdet`不能证明慢动作或真实镜数。
4. **声音与文字**：实际听到/字幕展示/未经核实三者分开。ASR不能证明配乐、音效或静音；抽帧未见字不能推导全片无字。
5. **卖点如何被证明**：原料、工艺、使用结果、价格等，与对应画面链接；广告宣传不写成已验证产品功效。
6. **可复用施工卡**：至少3个具体可抄点，给出镜头目的、建议时长、商品锁定条件、光线/构图、动作幅度、成片验收点；原片事实与建议参数清晰分开。教程重点还原可见流程与输入/输出关系。
7. **失败模式和边界**：文字变形、产品一致性、物理运动问题只能在可见证据支持时写；未看原图不可断言模型缺陷。记录哪些题材不可直接商业复用。
8. **证据附录**：100行帧表、计算出的占比、独立复核结果、未决问题与 supersedes。可另存JSONL，笔记提供可靠链接。

## 5. 独立复核与返修

- 蒸馏代理逐片提交新稿+帧表，状态 pending。独立复核者不代写自验结论，不信作者的「8/8」。
- 复核者按 video_id 固定种子另抽至少8帧，覆盖前/中/后；另加全部存疑边界、核心动作、UI/商品混淆段和100%/0%等极端断言。逐张读实际图或≤6格板，与具体帧行及正文逐条核对。
- 一条关键物体/动作错误、伪称已读、UI计特写或不存在证据：该片退回。针对错误段重读并修正文和帧表；再复核受影响部分。不因洗出比例不变而容忍错误描述。
- 主会话独立核对每片核心段及占比，合并复核结果。文本/视频不是文档视觉排版交付，不调用document judge来替代读帧。
- 媒体不可获取、图片工具不可用、额度硬停时保留 partial/BLOCKED。不得以自动重试、换像素法或把缺口删掉来变成完成；仅对可恢复错误有限重试。

## 6. 汇总口径

报告 unique canonical IDs：候选、下载可验、100帧视觉完成、独立复核通过、整体complete、商品成片入选、教程参考、非商品排除、失败/待补证。旧版和新版同一视频只算一片，washout不能重复加。已授权新版本可持续推进，未知内容不为凑数量晋级。

先运行本技能 `scripts/check_ad_evidence.py <sample_dir> <frames.jsonl>` 校验结构与算术，再做独立视觉内容复核。检查结果只表示结构通过，不表示视觉真读或笔记正确。
