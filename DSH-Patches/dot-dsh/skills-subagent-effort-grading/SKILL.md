# 子代理难度分级与思考等级派发

每次准备调用 `subagent` / `subagent_fork` 派发子代理之前，先评估任务难度，再在调用参数中带上 `reasoning_effort`，把思考等级随委托传给子代理。

## 难度 → 等级映射

| 等级 | 适用任务 | 示例 |
|---|---|---|
| **low** | 机械 / 检索 / 只读 / 无歧义的单步工作 | 读文件、查日志、格式化输出、单一明确指令、简单复制粘贴式小改动 |
| **high** | 需要推理、多步编排或判断权衡的工作 | 代码审查、跨文件改动、调试验证、方案评估、需要工具串联的任务 |
| **max** | 硬骨头：长链推理、高风险、复杂系统工作 | 跨模块重构、复杂 bug 定位、安全/逆向/加密分析、需要严谨论证的审核 |

## 判断维度（不是"计算量"，而是这五条）

1. **步数与编排复杂度**：一步完成 vs 需要串联多个工具/多轮。
2. **歧义与权衡**：任务描述是否明确，是否有需要做判断、取舍、权衡的地方。
3. **出错代价**：改坏了代价多大（只读检索 → 低；审核/生产改动 → 高）。
4. **推理链长度**：结论是否需要多步推导、长上下文综合。
5. **目标模型能力**：同一个等级对不同模型含义不同；等级值必须落在目标模型支持的集合里（活路由下先确认模型目录，未知值走透传或拒绝）。

## 派发流程

1. **读任务** → 按五个维度评估难度。
2. **选等级** → 对照上表；不确定时宁可高半档（质量优先），但明显机械的活别浪费。
3. **派发** → 调用时带 `reasoning_effort`，并在给用户的说明里写一句"这单给了 X 等级，因为……"。
4. **校准** → 收到结果后对照预期：质量不足就下次升档，明显杀鸡用牛刀就降档。把校准结果记入本会话的后续判断。

## 边界与注意

- **能自己顺手做的简单事不派子代理**：派发本身有开销（API 额度、上下文），1+1 级别的活直接做。
- **不传 reasoning_effort = 目标模型默认等级**：只有需要刻意控制时才必须传；默认留给模型自身行为。
- **配合活路由**：provider/model 已自动跟随父会话，本 skill 只管思考等级，两者互补。
- **AgentTeams 成员**：`agent_teams_add_member` 同样接受 `reasoning_effort`（同路由默认继承队长等级、显式传值优先），同一套分级准则适用。
